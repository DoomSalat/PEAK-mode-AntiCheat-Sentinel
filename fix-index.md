# PeakSentinel — Fix Index

1. **Obsolete (2026-10-20): WindowSkin removed when the window moved to Canvas + TMP.** `Reporting/WindowSkin.LoadGameFont` uses `Resources.FindObjectsOfTypeAll<Font>()` / `<TMP_FontAsset>()` (Rule 2: Find-методы). The game exposes no other reference to a legacy `Font` for IMGUI. The lookup runs on every window open until the font is found: if the game never loads it, every F6 press scans all loaded fonts and writes a log line.
2. **Fixed (2026-10-20): the kick is now retried every 5 s.** `Protection/BanGuard` kicks each banned actor once (`_kicked`). If the kick fails (event ignored, player stays), it is not retried until the host leaves the room.
3. **Fixed (2026-10-20): ItemLocator walks the game's own `Item.ALL_ITEMS` instead of every PhotonView.** Was: per-event scan of all PhotonViews. `ItemLocator.LooseItemNear` / `OwnedNear` walk `PhotonNetwork.PhotonViewCollection` on every non-host push, ground spawn and self-warp. Cheap at normal rates, but a push flood makes each packet cost O(all views). If it ever shows in profiling — keep a per-owner list of loose items instead.
4. **Fixed (2026-10-20): one slot helper — `ItemLocator.Carries` replaced `InstantiateAudit.Carries/Holds`.** Was: two slot lookups. `InstantiateAudit.Carries/Holds` (by itemID in host inventory) and `ItemLocator.Holds<T>` (by component) both walk `player.itemSlots` — could share one helper.
5. **Fixed (2026-10-22): one shared `Detection/KickClock`.** Was: duplicate kick clocks. `Protection/KickShield`, `Detection/PushAudit` and `Detection/KnockdownAudit` each keep their own `_kickedAt` dictionary filled from `RPCA_Kick` with the same 2 s window. One shared kick clock (registered once, read by all three) would remove the triple bookkeeping and keep the window in one place.
6. **Removed (2026-10-26) before release 1.1.6: temporary debug code.** `Patches/LifePatches` (stack trace on every ReviveCharacter and data.dead change of your character, LIFE lines in PeakSentinel.log) and `Detection/LifeTrace` (makes the router trace RPC_SyncOnJoin) were added to find what revived you after a refused cheat revive at 21:53:36. Remove both once the cause is found.
